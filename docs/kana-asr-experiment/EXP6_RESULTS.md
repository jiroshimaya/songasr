# gold 653クリップでの手法比較実験 (issue #6)

[#6](https://github.com/jiroshimaya/songasr/issues/6) の「実歌唱でのカナ認識精度の改善方針」を、gold データセット全653クリップ・統一指標で検証した記録。誤りパターンの事前分析は [`local/gold_dataset/IMPROVEMENT_IDEAS.md`](../../local/gold_dataset/IMPROVEMENT_IDEAS.md)（git管理外）、実験コードは `scripts/exp6/`（実行成果物は GPU機の `local/exp6/`）。

**結論(先に要約)**:
1. 「採点可 85/653 = 総崩れ」の大半は kanasim がカナ内スペースで KeyError を起こす採点バグだった。修正(d85c0ed)後の実態は「全手法がチャンス水準より2〜3割良い程度」。
2. 音響→カナ直接方式(baseline / #3 LoRA / +Demucs)はいずれも頭打ち。**#3 LoRA はホールドアウト1曲での優位が gold 全体に汎化しなかった**。
3. **英語ASR→テキスト→カナ化の経路が支配的に有利**。whisper-small の全曲転写テキストを e2k で単語カナ化しただけで既存最良になり、正解英語歌詞を与えた oracle は大差で勝つ(勝率74.7%)。**改善の主戦場は音響モデルではなくテキスト→カナ変換の様式適応**。
4. ただし Whisper の使い方に罠が2つ: 3〜8秒の切片単独転写は文脈を失い劣化、全曲転写の単語タイムスタンプは楽曲上で信頼できず固定区間への割当が一部壊滅する。**ASR自身のセグメントを処理単位にする**のが正しい設計。

## 評価設定

- データ: `local/gold_dataset/` 653クリップ/18曲（詳細は同封README）。
- 指標: **D/mora** = kanasim距離（スペース除去後）/ 正解カナのモーラ数。小さいほど良い。生距離は長さに比例し曲間比較が歪むため正規化した。モーラ数は小書き母音(ャュョァィゥェォヮ)を前の文字に併合して数えた素朴な定義。
- 校正値: **同一(identical) = 0 / チャンス（別の曲の無関係な正解カナを予測とみなす）= 7.62**。
- 勝率は baseline(mix) と両方採点可能なクリップでのペア比較。

## 結果 (全653クリップ)

| 手法 | 入力 | 採点可 | D/mora | 対baseline勝率 |
|---|---|--:|--:|--:|
| baseline (wav2vec2-espeak→カナ) | 原音声 | 561 | 5.66 | – |
| #3 finetuned LoRA | 原音声 | 525 | 5.77 | 52.7% |
| baseline | Demucs分離vocal | **611** | 5.64 | 51.1% |
| #3 finetuned LoRA | Demucs分離vocal | 518 | 5.72 | 54.0% |
| whisper large-v3 **切片単独**転写→e2k | 原音声 | 636 | 5.75 | 55.6% |
| whisper large-v3 切片単独転写→e2k | Demucs分離vocal | 632 | 5.98 | 53.6% |
| **whisper-small 全曲転写(english_sung)→e2k** | 原音声 | 636 | **5.49** | **57.8%** |
| whisper large-v3 全曲転写→**単語タイムスタンプで区間割当**→e2k | 原音声 | 632 | 7.45 (割当改善しても6.12) | 31.5% |
| **oracle: 正解英語歌詞(english_ref)→e2k** | – | 636 | **4.07** | **74.7%** |

### 読み取り

- **音響→カナ直接方式は全部だんご**(5.6〜5.8)。チャンス7.62比で25%前後の改善しかなく、どの曲でも実用レベルにない。
- **Demucs の効果は「崩壊の回復」**: baseline の採点可が 561→611 に増える(空出力や破綻の減少)。ただし精度(D/mora)はほぼ不変で、分離アーティファクトのためか whisper 系ではむしろ悪化。前処理としての優先度は低い。
- **#3 LoRA は gold 全体では baseline 以下**(5.77 vs 5.66)。TRAINING_NOTES の Stand By Me ホールドアウト優位は再現する(4.26 vs 5.83)が、フルバンド楽曲群には汎化しない。クリーンTTS弱教師の限界。
- **テキスト経由の優位と伸びしろ**: english_sung(whisper-smallの全曲転写)→e2k で 5.49。正解英語歌詞なら 4.07。この2つの差(≈1.4)が「ASRテキスト誤り」の寄与、4.07 と 0 の差が「e2k出力と gold の空耳様式の乖離」の寄与で、**後者の方が大きい**。
  - 例: gold `フォウィアー グローリアース` ↔ e2k `フォーウィーエアグロリアス` (D/mora 1.43)。意味・音は合っており、残差は縮約・長音・モーラ選択の様式差。
- **Whisper の罠**:
  - 切片単独転写(5.75)は english_sung(5.49)より悪い。3〜8秒の断片では文脈を失い、モデルを large-v3 に上げても取り返せない。
  - 全曲転写→単語タイムスタンプで固定区間に割当(7.45)は最悪。割当方法を工夫(単語中点方式)しても6.12。テキスト自体は english_sung と中央値0.90で一致しており、**大音量区間で単語タイムスタンプが大きくドリフトし、653中55クリップで割当が壊滅する**のが原因。中央値では 4.81 vs 4.50 と僅差だが、裾が平均を支配する。
  - → 実運用では「全曲を転写し、**ASR自身のセグメント境界**を単位としてカナ化する」設計にすべき(区間を外部から与えない)。

### 注意(公平性の限界)

- english_sung はデータセット生成時に whisper-small のセグメントとして得られ、正解歌詞行と match_score≥0.6 で対応づいたものだけがクリップ化されている。そのため e2k(english_sung) の 5.49 には選択バイアスがあり、「whisper全曲転写→e2k」を新規の曲に適用した際の期待値としてはやや楽観的。
- e2k は単語ごとの辞書式カナ化を無加工で連結しただけ。カナ変換側の改善余地(下記)は大きい。

## 改善方針(優先度順)

1. **P5': テキスト→カナの様式適応(最優先)** — oracle 4.07 に残る全差分がここ。e2k出力に対する空耳縮約(機能語弱化 `but with`→`バウィズ`、語末子音の母音落とし、長音・促音整理)をルール+goldでの軽量学習(seq2seq or n-gram置換)で適用する。gold 653ペアがそのまま教師データになる。
2. **P1': ASRテキスト品質の改善** — 全曲転写を whisper-small→large-v3 に上げ、ASR自身のセグメントを単位に評価する(選択バイアスのない形での再測定を兼ねる)。難曲(This Is Me 等の大合唱曲)のみ Demucs→全曲転写の併用を試す。期待改善は 5.49→4.1 方向で最大≈1.4。
3. **P4': 音響モデルをやるなら疑似ラベルを変える** — クリーンTTSではなく「実歌唱 + whisper→e2k(→縮約)の自動カナ」を教師にし、Demucs分離vocalで学習。ただし1,2で目的(歌えるカナ書き起こし)が達成できるなら不要になる可能性が高い。
4. **P3': 直接方式の救済(低優先)** — CTCデコードのkanasim収録モーラへの制約+カナLM。直接方式を捨てない場合のみ。

## 再現方法

```bash
# GPU機 (jiro-FRONTIER) のリポジトリルートで
.venv/bin/pip install e2k   # uv sync では消えるので注意
bash scripts/exp6/run_all.sh   # GPU空き待ち→全ステージ→採点 (成果物は local/exp6/)
.venv/bin/python scripts/exp6/report.py   # 集計レポート
```

- ステージは id 単位でレジューム可能(`scripts/exp6/run_exp.py <stage> --limit N`)。
- faster-whisper(CTranslate2) と demucs 用に venv 同梱 nvidia ライブラリへの `LD_LIBRARY_PATH` 設定が必要(run_all.sh が自動設定)。demucs は torchaudio I/O が壊れているため Python API + soundfile で I/O している。
